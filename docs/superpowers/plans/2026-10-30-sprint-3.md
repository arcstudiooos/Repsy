# Kinetic Sprint 3 Implementation Plan — Reliable Workout Experience

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Coaches edit programs safely: drafts autosave, saves create versions with history and conflict detection, and a client's own program can be changed without touching history. Clients keep logging through lost connectivity, can fix a log for 24 hours, and coaches can correct logs with a reason. Coaches can pause and resume a client's program without losing the training sequence.

**Architecture:** A `ProgramDraft` row per program holds unvalidated builder state; "Save changes" still goes through `commitProgramVersion`, which now also accepts a client copy and then reconciles that assignment's sessions (`reconcileSessions`: removed slots cancel unstarted sessions, added slots get new or revived sessions after the last one). Log edits after submission write append-only `SetLogRevision` rows. Pauses are `ClientPause` rows whose applied offset makes every reschedule a delta, so nothing shifts twice. Offline continuity is client-side only: an IndexedDB cache of the started workout, an IndexedDB outbox replaying the existing idempotent Sprint 2 endpoints, and a minimal service worker for the portal shell and in-progress workout pages.

**Tech Stack:** TypeScript (strict), Next.js 16 App Router (`src/proxy.ts` is the middleware), Better Auth, Prisma 7 + PostgreSQL 16 (RLS), Zod 4, React Hook Form, Tailwind + shadcn/ui, Vitest, Playwright + axe, `@date-fns/tz`, pg-boss (worker), IndexedDB (no wrapper library; `fake-indexeddb` for unit tests only).

**Spec:** `docs/implementation-plan.md` (Sprint 3 tickets S3-1…S3-6, Global Constraints, Review Focus, Target data model rows `ProgramDraft`, `SetLogRevision`, `ClientPause`) as amended by `docs/decisions.md` (D-001, D-002, D-003, D-004, D-008 #6 and clarification 2), plus the Sprint 3 sections of `docs/sprint-1-followups.md` and `docs/sprint-2-followups.md`. Where they conflict, decisions.md wins.

## Global Constraints

- Every read and write is scoped to the actor's active organization; never trust `organization_id` or `clientId` from input. Cross-tenant and other-client lookups return **404, not 403**.
- New tables (`program_drafts`, `set_log_revisions`, `client_pauses`) carry `organization_id`, composite `(fk, organization_id)` FKs to tenant parents, `ENABLE` + `FORCE ROW LEVEL SECURITY` with the `app_current_org()` policy; `packages/db/src/rls.test.ts` stays green.
- History never changes: workout and program versions stay immutable; a locked `workoutVersionId` never changes; completed, skipped and started sessions are never rescheduled, cancelled or re-pointed. Log edits never alter the workout version (D-008 clar. 2).
- Verbatim copy:

## Rulings made while planning (recorded in `docs/sprint-3-followups.md` by Task 3.9)

1. Only the client copy of a client's **active** assignment is editable; any other copy → 409 `CONFLICT` ("This program is no longer active for this client.").
2. A client copy keeps its days per week (it must equal the assignment's weekday count); changing it → 422 on `weeks`. Structural edits on client programs therefore add or remove whole weeks; day content and order can change freely (slots are positional, late resolution shows the new content).
3. Added slots are dated after the assignment's latest non-cancelled session (never before today in the client's zone), on the assignment's weekdays, in slot order. Removing a middle week leaves a gap; later sessions keep their dates.
4. Drafts are one per program, last write wins between tabs; conflicts are detected only at commit (`expectedVersion`).
5. A client's own edit within 24h also writes a `SetLogRevision` (reason optional). The coach's reason is shown to coaches only; the client sees "Corrected by your coach". A cleared set stays as an all-null row.
6. A pause starts today or later and lasts 1–90 days. Client status becomes `paused` when the pause is created; a worker job ends it on the resume date. Status changes to or from `paused` go through the pause API only.

## Review Focus

1. **Offline replay.** A workout logged offline, the page closed and reopened offline, then reconnected, leaves exactly one row per set and one completion on the server, also when a new program version was committed meanwhile. Test: Task 3.9 `offline.spec.ts`.
2. **Pause idempotency and DST.** Re-sending a pause, editing the resume date twice or resuming early never shifts a session twice, and a shifted session keeps 23:59 local across a DST change. Test: Task 3.6.
3. **Reconcile never touches history.** A commit that removes a slot cancels only `scheduled` sessions; an `in_progress` session keeps its locked version; completed weeks stay. Test: Task 3.2.
4. **Edit window boundary.** A client edit at 23h59m passes and at 24h01m is 403; a client of another org or a sibling client gets 404; coach correction without a reason is 422. Test: Task 3.5.
5. **Concurrent saves.** Two tabs commit from the same version: the second gets 409 and its draft is kept; another org's program draft is 404. Test: Tasks 3.1 and 3.3.
